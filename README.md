# RotP addon: Boy II Man (1.16.5, Forge 36.2.x, Java 8)

Авторы: **Gocimenya**, **inkegg** (идея, дизайн, модель и текстуры - inkegg).

## Сборка
1. Склонируй https://github.com/StandoByte/RotP-Addon-example и скопируй оттуда `gradlew`, `gradlew.bat`, папку `gradle/`
   (wrapper) в корень этого проекта (или просто положи `src/` и `libs/` из этого архива поверх шаблона).
2. Положи jar Ripples of the Past в `libs/` под именем `jojo-<версия>.jar` и впиши `<версия>` в `rotp_version` (gradle.properties).
3. `./gradlew genIntellijRuns` (или genEclipseRuns), затем `./gradlew runClient`; сборка jar: `./gradlew build`.
4. В игре: `/jojopower give @p rotp_boyiiman:boy_ii_man`.

## Управление (ПКМ-слоты)
1. Блок.
2. «Вызов» - наведись на цель. Цель-игрок получает кликабельное [Принять]/[Отказаться] (/b2m accept | decline),
   моб принимает сразу. Сам матч идёт в меню Камень-Ножницы-Бумага из основного мода.
3. «Принудительный вызов» - есть в слотах с самого начала, но НЕДОСТУПЕН, пока нет максимальной (5-й) решимости:
   применить можно только при уровне решимости 4 (индекс) И действующем эффекте Resolve. Эффект закончился - снова недоступен.
   Матч стартует сразу, без принятия/отказа цели (уже начатый матч доигрывается).
4-6. «Украденная способность 1-3» - слоты-пустышки; выигранные партии подменяют их на способности, отнятые у стенда цели.

## Визуал
Модель (`client/BoyIIManModel`) - штатный скелет RotP + авторские детали по референсу: остроконечный капюшон-шлем со светящимися
глазами и маской-клювом, массивные наплечники и грудная пластина с заклёпками, сегментированный живот, кожаные напульсники,
перчатки с шипами. Вместо ног - жёлто-зелёное пламя (ноги базового скелета не создаются).
Текстура 128x128: `textures/entity/stand/boy_ii_man.png` (UV всех боксов совпадают с кодом модели - правишь одно, правь и другое).
Иконки действий: `textures/action/*.png`, портрет стенда: `textures/power/boy_ii_man.png` (все 32x32).

## Механика
- Матч до 3 побед, ничья = переигровка. **С одним и тем же человеком можно играть сколько угодно раз.**
- Выиграл вор -> у цели отнимается ЕЩЁ ОДНА случайная способность ПКМ (кроме блока, действий аддона и уже украденных).
  У жертвы она блокируется (кулдаун, обновляется каждые 5 тиков), у вора доступна в слотах 4-6 (максимум 3 одновременно).
- Выиграла цель -> вор возвращает ОДНУ случайную из украденных у неё способностей (если нечего возвращать - просто ничего).
- Сила стенда: каждая украденная способность = треть. У жертвы -33% за каждую (атрибуты стенд-сущности: урон, скорость атаки,
  скорость), у вора баф Strength и баф атрибутов стенда за каждую. Во время партии каждый выигранный вором раунд дополнительно
  временно ослабляет цель на треть - до конца партии.
- Таймера нет: всё действует, пока не умрёт владелец стенда (жертва). Если умер вор - жертве всё возвращается.
  Вор держит кражу только у одного человека: победа над другим игроком возвращает прошлой жертве всё.
  Одну жертву не могут обворовывать двое одновременно.
- Если кто-то закрыл меню или вышел из игры - матч отменяется (украденное в прошлых партиях остаётся).
- Частиц у аддона нет вообще: эффекты кражи - только звук.
- Данные: NBT сущности (getPersistentData); список украденных способностей вору синхронизируется пакетом (net/).
- Config: `enableAbilitySteal` (кража способностей).

## Что проверить после первой сборки (API RotP менялся между версиями)
См. комментарии в коде; типичные места: имена классов `StandEntityLightAttack`/`StandEntityBlock` (в новых версиях
могут называться `...Action`), `TargetRequirement`, `ActionTarget.TargetType`, `StandEntityTask#getTick`,
`IStandPower.getStandPowerOptional`, `ModStandsInit.PART_4_NAME`, `HumanoidStandModel` (абстрактные методы поз).
Сверяйся с ExampleStandModel и InitStands из RotP-Addon-example для своей версии.

Новое в этой версии (проверить при первой сборке): `Action#replaceAction` в `StolenAbilityAction` (подмена трёх слотов на украденные
способности), `StandAction#isUnlocked` в `ForcedChallengeRPSAction` (теперь требует `ModStatusEffects.RESOLVE` на владельце), `IStandPower#unlockAction`,
`StandType#getDefaultHotbar(ControlScheme.Hotbar.RIGHT_CLICK)`, `JojoCustomRegistries.ACTIONS`.
Украденные StandEntityAction выполняются на стенд-сущности вора (Boy II Man), поэтому анимации/модель могут отличаться.

## Озвучка
Фразы владельца (Кэн Оянаги) - `sounds/user/owner_*.ogg`; сейчас это файлы-тишина (заглушки), текст фразы виден в субтитрах.
Замени .ogg на свои записи с теми же именами (mono, ogg vorbis) - код менять не нужно.
- `owner_summon` - призыв стенда; `owner_challenge` / `owner_forced` - обычный / принудительный вызов;
- `owner_round_win` / `owner_round_lose` - выигранный / проигранный раунд; `owner_steal` - украдена способность;
- `owner_match_win` / `owner_match_lose` - победа / поражение в матче.
Звуки самого стенда (`boy_ii_man_summon/unsummon/punch/steal`) пока ванильные; перепиши их в `sounds.json` на свои файлы.
Тексты фраз - в `lang/*.json`, ключи `rotp_boyiiman.subtitle.owner_*`. Играют только для игроков (у мобов голоса нет).

## Как проверить Forced Game в dev-клиенте
`/effect give @s jojo:resolve` НЕ подходит: RotP сразу снимает эффект, если шкала решимости пуста.
1. `/standlevel set @s 4` - уровень решимости 5 (индекс 4).
2. Набери шкалу решимости (получай урон/бей мобов) - когда она заполнится, включится эффект Resolve, и «Принудительный вызов» станет доступным (до этого слот серый). Закончится эффект - снова недоступен.
